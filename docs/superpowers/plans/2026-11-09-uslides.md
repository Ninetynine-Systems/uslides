# uslides Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build uslides. It is an offline-first, statically hosted slides PWA. Decks are plain Markdown with optional grid-placed boxes. It ships a SKILL file so AI agents can write decks.

**Architecture:** The code is split into four layers.
- A pure TypeScript **core** (`src/core`). It parses deck text into a `Deck` object and turns Markdown into safe HTML. It has no DOM, browser or React imports.
- A DOM **renderer** (`src/render`). It turns one `Slide` into a fixed-size 1920×1080 (or 1440×1080) element, and is shared by the preview, present mode, print and the exported HTML player.
- Browser **services**. Storage, share links, file sync and export each live in their own folder.
- A **React app shell** on top. It holds the CodeMirror editor, preview, deck list and present mode.

**Tech Stack:** TypeScript, Vite, React 19, CodeMirror 6, markdown-it, js-yaml, idb, vite-plugin-pwa, Vitest (with jsdom and fake-indexeddb), Playwright, GitHub Actions → GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-09-uslides-design.md`. Read it before any task. The spec is the authority on format rules. This plan is the authority on names, files and tests.

## Global Constraints

- Production address: `https://uslides.ninetynine.systems/`. Vite `base: '/'`. `public/CNAME` contains exactly `uslides.ninetynine.systems`.
- Export `APP_ORIGIN = 'https://uslides.ninetynine.systems'` from `src/config.ts`. All share links, `SKILL.md` and `llms.txt` use it.
- `src/core/**` must not import from `src/render`, `src/app`, `react`, or touch `window`/`document`. Task 2 adds an ESLint `no-restricted-imports` rule plus a Vitest test that greps for this.
- Defaults: grid `12x6`, aspect `16:9`, theme `light`. Stage sizes: 16:9 → 1920×1080, 4:3 → 1440×1080.
- Allowed URL schemes for links and images: `https:`, `http:`, `data:image/…`, and relative paths. Anything else is dropped.
- Allowed colours: `#rgb`, `#rrggbb`, `#rrggbbaa`, or a CSS named colour (a fixed list in `src/core/colors.ts`).
- Raw HTML in Markdown is never rendered (markdown-it `html: false`). The only comments read are `<!-- slide … -->` and `<!-- note: … -->`.
- Fonts are system fonts or bundled. No CDN requests at runtime.
- Commit messages must have no AI attribution lines (the owner's global rule). Use Conventional Commit prefixes (`feat:`, `test:`, `chore:`).
- Node 22 or newer. npm is the package manager.

## Review Focus

1. **Windows line endings and a byte-order mark (BOM) in files opened from disk.** Decks must parse the same as with `\n`. Pinned in Task 3.
2. **An unclosed `::: box`.** The box ends at the end of its slide with a warning. It must never swallow the slides after it. Pinned in Task 4.
3. **A corrupted or truncated share link.** Show "This link is damaged or incomplete" and create no deck. Pinned in Task 10.
4. **The same deck open in two tabs.** A save from a stale tab must not silently overwrite newer text. The stale tab shows "This deck changed in another tab" and reloads it. Pinned in Task 8.
5. **A deck with a multi-megabyte pasted image.** Typing in the editor stays responsive, because the `data:` URI is folded and the preview re-renders debounced. Pinned in Task 12.

  - Lines like `----` or ` --- ` (with spaces) do not split. Only a line that is exactly `---` does.
  - An empty body → 1 empty slide. A trailing `---` at the end → no empty last slide.
  - Each `range` slices back to that slide's exact text from the source.
